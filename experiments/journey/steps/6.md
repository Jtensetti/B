# Step 6: dist-tags

Keep everything from before. A required "range" may now be one of two npm dist-tags instead of a range:

- `"latest"`: the highest available version without a prerelease tag.
- `"next"`: the highest available version, prereleases included.

A pin still takes precedence over a dist-tag. If no available version qualifies, the package is unresolved.

Example input:

    {"requires": {"a": "latest", "b": "next", "c": "latest"}, "available": {"a": ["1.0.0", "1.1.0", "2.0.0-beta.1"], "b": ["1.0.0", "2.0.0-beta.1"], "c": ["0.1.0-alpha.1"]}}

Example output:

    {"resolved": {"a": "1.1.0", "b": "2.0.0-beta.1"}, "unresolved": ["c"], "suggestions": {}, "summary": {"resolved": 2, "unresolved": 1, "suggested": 0}}
